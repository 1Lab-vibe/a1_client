# Отключение синхронизации

Карточка со статусом `connected` показывает «Отключить синхронизацию».
Клиент отправляет на существующий `/api` action `disconnectIntegration`
с `payload: { provider }` и текущими `company_id`, `user_id`, `token`.
После подтверждения перечитывает `getIntegrations`; до завершения запроса
и обновления списка кнопки заблокированы.

## Серверный контракт

```json
{
  "ok": true,
  "data": {
    "provider": "bitrix24",
    "status": "disconnected"
  }
}
```

Сервер должен проверить сессию и право управления интеграциями выбранной
компании, остановить синхронизацию выбранного подключения и сохранить статус
`disconnected`. Операция должна работать без обращения к неоплаченному
Bitrix24 и быть идемпотентной. Сохранённые CRM-данные удалять не нужно.
Необходима проверка всех источников запуска: расписание, очередь, повторные
попытки и вебхуки. Уже выполняющиеся задания не должны включать подключение
обратно. Нельзя отключать одноимённые подключения других компаний.

Секреты остаются в существующем зашифрованном серверном хранилище age/SOPS;
клиент не получает токены провайдера. Миграция БД в клиентском изменении отсутствует.

`finsph_bitrix24_ru` — отображаемое название подключения; ключ провайдера —
`bitrix24`. Серверная реализация находится в `a1-dev-ops`:
`scripts/deploy-integration-disconnect.mjs` обновляет актуальные live workflow
`ui_integrations_service` и `in_webhook_inbound`, после проверок в транзакции
с откатом. Перед выпуском клиента применить этот патч и обновить API:
`bitrix24-connect/runtime.ts` блокирует импорт, исходящие команды и вебхуки
отключённого подключения до чтения секретов или обращения к Bitrix24.
Существующее расписание выбирает только подключённые интеграции и порталы.
До и после серверных изменений проверяется UTF-8 и mojibake.

Пустой ответ, список интеграций вместо подтверждения и ответы с ошибкой
не считаются успешным отключением. Клиент выводит ошибку и сохраняет карточку.
