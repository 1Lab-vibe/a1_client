# Снабжение: клиент и подключение

Дата: 2 ноября 2026. Контракт: `procurement.v1`.

## Навигация

«Снабжение» — раздел верхнего уровня между «Отчетами» и OPS. Сохранённый порядок меню получает новый пункт после отчётов. Прямая ссылка: `/#/supply`; старые `/#/ops/supply` продолжают открывать раздел.

В рабочем интерфейсе используется только серверный клиент. Демопереключателя, демонстрационных данных и build-флага готовности нет. Mock и fixtures используются исключительно тестами и не входят в production bundle.

Каталог, фильтры, карточки, разбор текста/файла, анализ, история и экспорт запрашиваются у сервера. Одна текстовая позиция на строку, например `УШМ 125 мм — 2 шт`. Количество и единица проверяются пользователем перед анализом. Клиент не подменяет ошибки тестовыми результатами.

## Транспорт

- `POST /api/procurement/command`: JSON envelope с версией, UUID запроса, компанией, действием и payload.
- `POST /api/procurement/files`: multipart `file`, `company_id`.
- Авторизация: Bearer существующей пользовательской сессии, same-origin; ключи сервера браузеру не передаются.
- Nginx клиента проксирует `/api/procurement/` в `a1-api:4000` в общей Docker-сети. Docker DNS обновляется каждые 10 секунд. Старый `/api` обслуживает существующий Traefik router.
- Vite проксирует этот же префикс в `https://api.a1os.ru` без переписывания в n8n webhook.
- Защищённые ссылки скачивания выдаёт сервер; клиент допускает только HTTP(S) и проверяет срок действия.

Схемы валидируют envelope, request_id, версию и данные ответа. Принимаются серверные плоские категории с parent_id, источники с name, плоская карточка товара, строковые предупреждения распознавания, пустой progress и уже завершённое задание при повторе команды. Отсутствующий observed_at остаётся неизвестным. В исходящих фильтрах неизвестный stock_known опускается; процент ограничения цены передаётся числом.

## Восстановление

- Задание: `/#/supply?company=<company_id>&job=<job_id>`. Старые ссылки с `mode=mock` не открывают демонстрационное задание на сервере.
- Черновик и неподтверждённая команда: sessionStorage, ключ пользователя/компании с суффиксом `:live`. Старые демочерновики не используются.
- Повтор команды сохраняет request_id и Idempotency-Key. Двойное нажатие блокируется. Идемпотентность и доступ проверяет сервер.
- Смена компании отменяет запросы. Опрос последовательный, учитывает poll_after_ms и Retry-After, при скрытой вкладке приостанавливается.
- При добавлении распознанных строк позиции становятся уникальными; исходная строка файла остаётся в source_ref.row.
- Ошибка HTTP, несовместимый ответ и failed job показываются как ошибки, а не как пустой успешный результат.

## Проверки

`npm run test:procurement`, `npm run check:procurement-encoding`, `npm run build:procurement-check`.

Для браузерного прогона: `npm run dev -- --host 127.0.0.1`, затем `npm run test:procurement:ui`. Playwright использует синтетическую сессию и HTTP-подмену из `tests/procurement-http-fixture.ts`, включая серверные формы ответов. Внешние запросы блокируются. Проверяются старый порядок меню, отсутствие демо, каталог, фильтры, карточка, распознавание, анализ, восстановление, экспорт, ошибки, смена компании и гонки запросов. Эти тесты не заменяют проверку развёрнутого API.

Артефакты: `output/playwright` (игнорируются Git). Production-клиент: `https://a1.a1os.ru`, `/opt/a1-client`, контейнер `a1-client`. Серверный `a1-api` должен поддерживать procurement маршруты; клиентского переключателя включения нет. Инструкции: `docs/DEPLOY.md`. Миграций БД в клиентском репозитории нет.
